Import PFX certificate

Upload a PKCS#12 bundle (.pfx / .p12) containing the certificate, full chain, and private key. FlexEdgeAdmin extracts the components, writes them in certbot's layout under ${FEA_PFX_DIR} (default /config/imported-certs/), and registers a tracked certificate the existing deploy pipeline can ship to an engine. Re-importing the same Common Name replaces the on-disk files in place.

Bundle must contain the private key AND the end-entity certificate. Intermediate / root certs are optional but recommended.
Leave empty for unprotected bundles. The password is used once to decrypt the upload — it is never stored.
Used as the tracked-certificate name and the on-disk directory slug. Defaults to the cert's Common Name, then the first Subject Alternative Name. Reject a PFX with no identifiers by supplying one here.
Trust the source. A PFX with a malicious private key becomes the TLS identity on whichever engine you deploy it to. Import only bundles you generated or received over a verified channel.
Cancel
What gets written to disk

For a successfully parsed bundle named api.example.com:

${FEA_PFX_DIR}/api.example.com/
├── cert.pem        end-entity certificate (PEM)
├── chain.pem       intermediates + root (PEM, may be empty)
├── fullchain.pem   leaf + chain — read by the TLS deploy pipeline
└── privkey.pem     unencrypted private key (chmod 0600)

Files are included in /admin/backup so restore is reissue-free. Wildcard CNs (*.example.com) become wildcard.example.com as the directory slug.
